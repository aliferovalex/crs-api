# Единый пакет помещения

Все 12 прежних типов пакетов используют один файл `ПакетПомещенияОбъекта.os`.
Отдельные реализации создания константы, справочника, документа, перечисления,
модуля и форм, изменения внешнего потока и удаления формы удалены. Старые имена
типов зарегистрированы в `lib.config` как алиасы этого файла; их конструкторы
с прежними аргументами продолжают работать.

Подготовка через библиотеку теперь возвращает **ПакетПомещенияОбъекта**.
Проверки вида `ТипЗнч(Пакет) = Тип("ПакетСозданияКонстанты")` для результатов
подготовки следует заменить проверкой операции и класса метаданных:

```bsl
Если ПравилаПакетовХранилища.ЭтоПакет(Пакет, "Создание", "Constant") Тогда
    // Создание константы.
КонецЕсли;
Сообщить(Пакет.ВидОперации());   // Создание, Изменение, Удаление
Сообщить(Пакет.ВидМетаданных()); // Constant, CatalogForm, CommonModule...

Результат = Клиент.ПоместитьПакет(Пакет, "Комментарий помещения");
```

`ПоместитьПакет` выбирает проверки и процедуру подтверждения результата по
операции. Создание возвращает новый объект, изменение — обновлённый объект,
удаление формы — обновлённого родителя. Захваты и актуальность версии проверяются
как прежде. Специализированные методы помещения сохранены и принимают общий тип.

Общая модель включает бинарный пакет, версию хранилища, исходные объекты,
запрошенные описания, изменённые описания, внешние потоки, признаки и код версии.
Создание описаний и проверка бинарного заголовка вынесены в общую реализацию.
`ТелоЗапросаНаПомещениеПакета` формирует один RPC-конверт `DevDepot_commitObjects`
для всех операций; прежние функции формирования запросов вызывают его.

| Операция | Что различается |
| --- | --- |
| Создание | Новый UUID, ожидаемый класс объекта и родителя, перечень согласованных исходных объектов |
| Изменение | Существующий UUID и исходная версия; при замене кода или интерфейса — один внешний поток |
| Удаление | Форма в `objectsToRemove`, новый родитель, оба исходных захвата |

Различия заданы правилами в `ПравилаПакетовХранилища.os`: операция, класс
метаданных, класс родителя, допустимый профиль платформы и состав признаков.
Для форм создание требует один снимок родителя; для верхних объектов используется
прежний набор снимков. Новый поток общего модуля имеет action=1, поток новой
формы — action=0. Признак изменения коллекции констант и пустые признаки новых
справочников, документов, перечислений и модулей сохраняются.

Правила копируются при создании пакета и доступны через методы чтения.
Изменение переданной структуры правил не меняет операцию уже созданного пакета.
Старый алиас не позволяет переопределять его класс и операцию дополнительным
аргументом. Импорт XML нельзя смешивать с готовым результатом сериализатора.

Канонический конструктор для результатов Python:

```bsl
Правила = ПравилаПакетовХранилища.Параметры("Создание", "CatalogForm");
Пакет = Новый ПакетПомещенияОбъекта(РезультатPython, Снимки,
    ИмяХранилища, ВерсияПлатформы, Правила);
```

Для изменения внешний результат и один снимок передаются тем же конструктором.
Для удаления — массив снимков `[родитель, форма]`. При импорте подготовленного
нативного запроса сохранены `Новый ПакетПомещенияОбъекта` и `ЗаполнитьИзЗапроса`;
перед отправкой описание существующего объекта проверяется явно либо получается
единым методом помещения по UUID.

Нативные Python-преобразователи сохраняют свои различия: XML справочника, формы,
модуля и корня имеют разные внутренние схемы. Их результат помещается через
общую модель; объединение классов пакетов не добавляет поддержку новых свойств.

Проверено: 15 RPC-конвертов на прежних проверочных данных совпали с исходной
реализацией после нормализации случайного bindID. Все 11 специализированных
конструкторов проверены также через канонический вход. На действующем хранилище
подготовлены создание, изменение и удаление формы без помещения.

При проверке обнаружена историческая связь справочника с ранее удалённой формой.
Создание формы теперь сохраняет такие связи, отсутствующие в текущем контексте,
при совпадении снимка и контекста. Ссылки на посторонние активные объекты и
некорректные флаги по-прежнему отклоняются. Добавлена отдельная проверка этого случая.

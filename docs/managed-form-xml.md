# Общий преобразователь формы из XML

Создание и изменение используют `managed_form_xml.convert`: весь `Ext/Form.xml`
преобразуется в нативный поток `UUID.0`, текст `Ext/Form/Module.bsl` записывается
в тот же поток. Python 3.9+, стандартная библиотека; установленная платформа,
временная база и CF для работы библиотеки не нужны.

```bsl
Пакет = Клиент.ПодготовитьИзменениеФормы(Форма,
    "C:\\export\\Form.xml", "C:\\export\\Module.bsl", ПутьPython);
Клиент.ЗахватитьОбъект(Форма);
Обновлённая = Клиент.ПоместитьИзменениеФормы(Форма, Пакет, "Интерфейс из XML");
Клиент.ОтменитьЗахватОбъекта(Обновлённая);

Пакет = Клиент.ПодготовитьСозданиеФормыИзXML(Справочник, "НоваяФорма",
    "C:\\export\\Form.xml", "C:\\export\\Module.bsl", ПутьPython);
Клиент.ЗахватитьОбъект(Справочник);
Новая = Клиент.ПоместитьСозданиеФормыСправочника(Пакет, "Форма из XML");
// Захваты формы и родителя сохраняются; освобождайте их после помещения.
```

Путь к модулю необязателен. Если он пропущен, при изменении сохраняется текущий
модуль, при создании используется пустой. Переданный пустой файл очищает модуль.
Список полей берётся целиком из XML: отсутствующие поля удаляются, порядок,
имена, идентификаторы и привязки задаются XML. UUID существующей формы сохраняется;
создание выделяет новый UUID и обновляет список форм родителя. Для привязок
пользовательских реквизитов UUID берутся из актуального тела справочника.
Свойства объекта формы вне `Ext/Form.xml` пока не изменяются.

Первая реализованная XML-схема — управляемая форма элемента справочника,
`version="2.21"`, `UseForFoldersAndItems=Items`, стандартная `AutoCommandBar`,
единственный основной `Object`, плоский `ChildItems` из `InputField` с `DataPath`.
Поддерживаются привязки `Object.Code`, `Object.Description`, пользовательские
реквизиты справочника; проверено на строковом реквизите. Допускаются стандартные
узлы `ContextMenu` и `ExtendedTooltip`; их служебные идентификаторы нормализуются
платформой при выгрузке. Самостоятельное изменение этих идентификаторов не поддерживается.

Это ещё не преобразователь произвольной XML-формы. Кнопки, группы, таблицы,
команды, события, дополнительные реквизиты формы и другие XML-свойства вызывают
ошибку вместо пропуска. Их правила нужно добавлять в общий преобразователь,
без отдельных публичных методов для каждой операции над элементом.
Нативная основа сохраняет остальные внутренние данные проверенного профиля;
создание использует основу по виду формы, изменение — текущий поток сервера.
Существующие методы создания форм документов и общих форм также используют
общий вход для нативного потока, но загрузка их `Form.xml` пока не реализована.

Проверяются исходная версия объекта, версия внешнего потока, контекст родителя
и актуальность хранилища. Получение текущего потока сохраняет прежний предел
16 МиБ для пакета полной версии. Профиль legacy; проверенная платформа 8.5.1.1529.
Алгоритм внутренних версий остаётся экспериментальным.

Нативная проверка: версия 17 изменила существующую `CRSAPI_TestCatalogForm`,
версия 18 создала `CRSAPI_XMLWholeForm` из того же XML и модуля. Загрузка CF в
отдельную базу и XML-выгрузка подтвердили порядок Description/Code/AttributeInput,
привязки и текст модуля в обеих формах. Свойства и UUID существующей формы,
тела остальных объектов, кроме списка форм родительского справочника, сохранены.

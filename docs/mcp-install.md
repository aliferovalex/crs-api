# Установка MCP CRS API

Руководство для пользователя, подключающего MCP к своему клиенту, и агента,
выполняющего установку или работающего с инструментами. Примеры — для Windows
и PowerShell. Все пути, адреса и имя профиля `local` в примерах нужно заменить
своими. Профиль `lab` из лаборатории разработчика у других пользователей отсутствует.

## Для пользователя

### 1. Подготовить зависимости

| Компонент | Для чего нужен |
| --- | --- |
| Python 3.9+ | Запуск MCP и JSON CLI; сторонние Python-пакеты не нужны |
| OneScript с `opm` | Выполнение библиотеки CRS API; проверена версия 1.8.2.1 |
| Зависимости OneScript из `packagedef` | `xml-parser` 0.1.1 и `1connector` 2.1.3 |
| ibcmd-rs | XML/BSL-чтение, создание рабочей основы и подготовка изменений; проверена версия 0.4.1 |
| Доступное хранилище 1С и учётная запись | Адрес HTTP(S) или TCP, версия платформы, логин и пароль |

Для подключения, поиска, нативного чтения и работы с пользователями ibcmd-rs
не обязателен. Для чтения исходников XML/BSL он нужен. Проверенная версия сервера
хранилища — 8.5.1.1529; ограничения совместимости находятся в [status.md](status.md).
Для чтения достаточно учётной записи хранилища с соответствующими правами.

Нужны исходники именно этого форка, содержащие `tools/crs_mcp.py`,
`src/agent_mcp.py`, `tools/crs.py` и `src/cli_bridge.os`.
Исходники: [aliferovalex/crs-api](https://github.com/aliferovalex/crs-api).
Пакет `opm install crs-api` из публичного хаба может содержать другую версию
без MCP. Если MCP-файлы ещё не опубликованы в Git, используй подготовленную
рабочую копию или дождись их публикации: установка старой версии их не добавит.

Помести исходники, например, в `C:/work/crs-api`. Установи зависимости из корня:

```powershell
Set-Location 'C:/work/crs-api'
opm install -l
```

Команда устанавливает зависимости `packagedef` в `oscript_modules`. Для запуска
MCP не нужны зависимости разработки (`--dev`). При ошибке доступа к хабу настрой
доступное зеркало `opm` либо используй уже установленные зависимости, указав
их каталог в `runtime.module_path`.

Скачай подходящую сборку ibcmd-rs из
[официальных выпусков](https://github.com/Untru/ibcmd-rs/releases) и распакуй,
например, в `C:/tools/ibcmd-rs`. Запиши реальный путь к исполняемому файлу.

Проверь доступность программ:

```powershell
& 'C:/Program Files/Python39/python.exe' --version
& 'C:/Program Files/OneScript/bin/oscript.exe' -version
& 'C:/tools/ibcmd-rs/ibcmd-rs.exe' --version
& 'C:/Program Files/Python39/python.exe' 'C:/work/crs-api/tools/crs_mcp.py' --help
```

MCP-клиент сам запускает процесс сервера через stdio. Веб-публикация MCP и
отдельный HTTP-порт ему не нужны. Сервер хранилища 1С должен уже работать:
этот MCP не устанавливает и не запускает его автоматически.

### 2. Создать настройки подключения

Создай каталоги `C:/work/private` и `C:/work/configuration`. Первый — для локальных
настроек, второй — существующая рабочая папка, относительно которой MCP будет
разрешать пути. Создание XML-основы внутри неё выполняется отдельным инструментом.

Сохрани `C:/work/private/crs.config.json`:

```json
{
  "schema": 1,
  "repositories": {
    "local": {
      "url": "tcp://127.0.0.1:1542/Example",
      "platform": "8.5.1.1529",
      "username": "reader",
      "password_env": "CRS_REPOSITORY_PASSWORD",
      "cache_directory": "C:/work/private/cache/local"
    }
  },
  "runtime": {
    "oscript": "C:/Program Files/OneScript/bin/oscript.exe",
    "ibcmd": "C:/tools/ibcmd-rs/ibcmd-rs.exe",
    "module_path": "C:/work/crs-api/oscript_modules"
  }
}
```

`local` — имя профиля для аргумента `profile`. Можно описать несколько хранилищ,
каждое со своим именем, переменной пароля и каталогом кэша. `platform` — полная
версия из четырёх чисел; она не определяется автоматически. Пароль в URL
не передаётся. HTTP(S)-адрес укажи из действующей публикации хранилища.

Относительные пути в этом JSON считаются от папки файла настроек. Пути,
передаваемые инструментам, — от `--workspace`. Кэш и результаты подготовки
должны быть доступны процессу MCP на запись.

Для большой конфигурации добавь объект `limits` внутрь профиля `repositories.local`.
Все значения — положительные целые байты; можно изменить отдельные бюджеты
транспорта, нативного контейнера, CF и XML. [Описание и пример](status.md#размеры-и-защитные-лимиты).
CLI/MCP автоматически передают политику OneScript и Python и используют файловый
приём ответов. Первоначальный пакет кэша декодируется в файл без общей XML/base64
строки. После этого декодированные CF-образы и XML-компиляция всё ещё требуют
памяти: повышенный лимит не гарантирует, что произвольная конфигурация поместится
в RAM. Профили и пароли для этого менять не требуется.

### 3. Передать пароль

Основной способ — переменная окружения `CRS_REPOSITORY_PASSWORD`, существующая
в процессе запуска MCP. `password_env` содержит её имя. Не добавляй пароль
в аргументы запуска, обращения к агенту или опубликованные настройки.

При запуске Codex CLI из PowerShell можно ввести пароль без вывода на экран:

```powershell
$crsSecret = Read-Host 'Пароль хранилища' -AsSecureString
$crsCredential = [System.Management.Automation.PSCredential]::new('reader', $crsSecret)
$env:CRS_REPOSITORY_PASSWORD = $crsCredential.GetNetworkCredential().Password
codex
```

Этот способ предназначен для непустого пароля. Переменная задаётся только
в текущем процессе PowerShell и его потомках; уже открытое desktop-приложение
её не получит. Для desktop-клиента и пустого пароля используй приватный загрузчик
ниже либо свой менеджер секретов, устанавливающий переменную перед запуском MCP.

**Приватный загрузчик для desktop-клиента и пустого пароля.** Создай
`C:/work/private/crs-secrets.json`, доступный только нужному пользователю:

```json
{"CRS_REPOSITORY_PASSWORD":""}
```

Пустая строка означает пустой пароль. Для непустого пароля заполни значение
в локальном файле с корректным JSON-экранированием. Символы `!` и `$` сохраняются
как есть. Этот файл содержит секрет в открытом виде: храни его вне Git и не
передавай агенту для вывода или публикации.

Сохрани `C:/work/private/start_crs_mcp.py`:

```python
import json
import os
from pathlib import Path
import runpy
import sys

root = Path('C:/work/crs-api')
private = Path('C:/work/private')
secrets = json.loads((private / 'crs-secrets.json').read_text(encoding='utf-8-sig'))
os.environ['CRS_REPOSITORY_PASSWORD'] = secrets['CRS_REPOSITORY_PASSWORD']
entry = root / 'tools/crs_mcp.py'
sys.argv = [str(entry), '--config', str(private / 'crs.config.json'),
            '--workspace', 'C:/work/configuration']
runpy.run_path(str(entry), run_name='__main__')
```

Загрузчик не запрашивает пароль в stdin: этот поток занят протоколом MCP.
Python передаёт установленную переменную дочернему CLI, включая пустое значение
на Windows. Для нескольких профилей аналогично установи нужные переменные.

### 4. Подключить к Codex

Добавь отдельную секцию в `%USERPROFILE%/.codex/config.toml`, сохранив остальные
настройки. Настройка MCP описана в
[официальной документации OpenAI](https://learn.chatgpt.com/docs/extend/mcp).

Если используешь переменную окружения из шага 3:

```toml
[mcp_servers.crs-api]
command = "C:/Program Files/Python39/python.exe"
args = ["C:/work/crs-api/tools/crs_mcp.py", "--config", "C:/work/private/crs.config.json", "--workspace", "C:/work/configuration"]
env_vars = ["CRS_REPOSITORY_PASSWORD"]
startup_timeout_sec = 30
tool_timeout_sec = 960
```

Если используешь приватный загрузчик, вместо этой секции добавь:

```toml
[mcp_servers.crs-api]
command = "C:/Program Files/Python39/python.exe"
args = ["C:/work/private/start_crs_mcp.py"]
startup_timeout_sec = 30
tool_timeout_sec = 960
```

Выбери один вариант; две секции с одинаковым именем недопустимы. Для доверенного
проекта можно использовать его `.codex/config.toml`. Имя сервера в клиенте —
`crs-api`, имя профиля внутри него — `local`; это разные настройки.

Проверь регистрацию:

```powershell
codex mcp get crs-api
codex mcp list
```

Регистрация ещё не проверяет соединение с хранилищем. Перезапусти клиент Codex,
чтобы он загрузил сервер и каталог инструментов; для варианта с переменной
окружения запусти его из подготовленного процесса. Затем выполни проверку ниже.

Для другого MCP-клиента с настройкой `mcpServers` вариант с загрузчиком выглядит
так (проверь формат своего клиента):

```json
{
  "mcpServers": {
    "crs-api": {
      "command": "C:/Program Files/Python39/python.exe",
      "args": ["C:/work/private/start_crs_mcp.py"]
    }
  }
}
```

Это локальный stdio-сервер. Указывать TCP-адрес хранилища в поле URL MCP-клиента
не нужно: адрес хранилища остаётся в `crs.config.json`.

### 5. Проверить настоящие вызовы

Попроси агента в новом или обновлённом чате:

> Проверь MCP crs-api на профиле local. Вызови crs_connect, затем
> crs_objects_search с kind=CommonModule и limit=1. Если объект найден,
> прочитай его через crs_objects_read с format=xml. Покажи статусы и имена
> полученных файлов. Выполни crs_users_list и сообщи только количество.
> Используй прямые MCP-вызовы; ничего не меняй в хранилище.

Ожидается одиннадцать инструментов; `crs_users_apply` и `crs_changes_commit` по умолчанию отсутствуют.
`crs_connect` должен вернуть `ok=true`, `connected=true` и UUID версии.
Нулевой результат поиска допустим: тогда выбери существующий объект другого
класса. Для XML-чтения проверь `representation.status=available` и список файлов.
`unavailable` означает, что нативное чтение прошло, но XML-преобразование недоступно.

Список инструментов не содержит паролей и хешей. Чтение пользователей требует
достаточных прав: отказ этого инструмента не означает отказ поиска объектов.
Не повышай права пользователя ради прохождения проверки без отдельного решения.

### 6. Подключить навык агента

Если агент работает в checkout CRS API, его `AGENTS.md` уже ссылается на
[навык 1c-repository](../skills/1c-repository/SKILL.md).

Для другого проекта можно добавить в его `AGENTS.md`:

```markdown
Для работы с хранилищем 1С используй MCP crs-api и профиль local.
Инструкция: C:/work/crs-api/skills/1c-repository/SKILL.md.
По умолчанию разрешено чтение. Доработки готовь локально с исходной версией и diff.
Изменения пользователей требуют явного одобрения конкретного плана.
```

Если нужен навык во всех проектах, скопируй папку `skills/1c-repository`
в каталог навыков клиента, для Codex — `%USERPROFILE%/.codex/skills/1c-repository`.
Существующий одноимённый навык сначала сравни; не перезаписывай его автоматически.
При отдельной установке укажи агенту путь checkout или `CRS_API_HOME`, чтобы он
нашёл связанные документы. Это подсказка навыку, не параметр конфигурации сервера.
Обновление копии навыка выполняется отдельно от обновления checkout.

### 7. Необязательная запись пользователей

Для обычного чтения этот шаг не нужен. Чтобы включить `crs_users_apply`, добавь
`--allow-user-writes` к аргументам `tools/crs_mcp.py`. Если используешь загрузчик,
добавь его в `sys.argv` загрузчика. Перезапусти MCP-клиент.

Перед записью нужны `crs_users_plan`, проверка `before/after` и явное разрешение
на конкретную операцию. Для существующего пользователя передаётся `expected`
из `before`, а также `execute=true`. Включение инструмента не выдаёт серверных
прав и не заменяет одобрение. Для помещения конфигурации независимо включается
`--allow-configuration-writes`. Он добавляет `crs_changes_commit`, но не разрешает
агенту выполнять произвольные помещения. Понадобится одобрение конкретного плана.
Контракты и ограничения — в [status.md](status.md#mcp-сервер).

## Для агента

### При установке

1. Найди checkout с `tools/crs_mcp.py`, проверь Python, OneScript и каталог
   зависимостей. Для XML/BSL проверь ibcmd-rs. Не подменяй текущий форк пакетом
   из хаба без проверки наличия MCP-файлов.
2. Получи профиль, адрес, полную версию платформы и пути от пользователя или из
   существующих настроек. Не угадывай их и не выводи весь файл с учётными данными.
3. Создай отдельные настройки и workspace. Пароль передавай через окружение или
   приватный загрузчик. Не добавляй секреты в Git, TOML клиента или командную строку.
4. Добавь секцию MCP, сохраняя настройки остальных серверов. Запрос установить MCP
   не разрешает менять пользователей, захваты или содержимое реального хранилища.
5. Проверь наличие инструментов именно в текущем чате. Если их нет, сообщи,
   что клиенту нужно перечитать настройки или перезапуститься. Запуск CLI вручную
   проверяет CLI, но не доказывает доступность MCP-инструментов в чате.
6. Выполни только проверку чтением из шага 5. Отдельно укажи регистрацию,
   доступность инструментов, авторизацию и результат XML-преобразования.

### При использовании

Вызывай инструменты по их фактическим именам в клиенте: он может добавлять
префикс пространства имён. Аргументы передаются напрямую, например для
`crs_objects_search`:

```json
{"profile":"local","kind":"CommonModule","query":"Обмен","limit":20}
```

Не добавляй оболочку CLI `schema/action/params`. Начни с `crs_connect`, затем
поиска; используй UUID из свежего результата для `crs_objects_read`.
Проверяй `isError`, `structuredContent.ok` и `representation.status`.
Если клиент отдаёт только текстовый `content`, разбери JSON из него.
Учитывай `next_offset` поиска; это не полнотекстовый поиск BSL.

Для локальной доработки используй `crs_workspace_init` и `crs_changes_prepare`
с полной XML-выгрузкой. Не смешивай исходную основу с правками, сохраняй diff
и план. `output_directory` — новый каталог вне исходной выгрузки.
Подготовленный пакет не означает выполненное помещение.

Если полный экспорт не поддержан компилятором, `crs_workspace_init` принимает
`allow_partial=true`: полный CF сохраняется, XML получает карту покрытия,
рабочая папка создаётся выборочной. `crs_workspace_materialize` копирует файлы
выбранных UUID для работы. Отсутствующие XML не означают удаления; полная
подготовка `crs_changes_prepare` для такой папки пока запрещена. Доступен адресный
путь изменения отдельно хранимых модулей. См. [частичную основу](status.md#частичная-xml-основа).

Для правки одного существующего BSL-модуля используй `crs_modules_prepare`
с полным новым `source_file` и ожидаемым SHA256 исходного текста. Полный CF
и кэш для этого не требуются. Точный контракт и ограничения описаны в
[адресной подготовке модуля](status.md#адресная-подготовка-bsl-модуля).

При конфликте чтения получи свежий снимок. При неопределённом результате записи
проверь фактическое состояние; не повторяй запись автоматически. Работа с
пользователями и границы разрешений описаны в
[навыке](../skills/1c-repository/SKILL.md#пользователи).

## Диагностика

### Помещение подготовленных изменений

Добавь `--allow-configuration-writes` в аргументы сервера (или его приватного
загрузчика) и перезапусти MCP-клиент. `crs_changes_plan` и `crs_changes_status`
доступны и без этого флага; он включает только `crs_changes_commit`.
Для записи нужны права пользователя хранилища и явное одобрение конкретного
плана с diff, целевым хранилищем и комментарием.

После `crs_modules_prepare` или `crs_changes_prepare`:

```json
{"name":"crs_changes_plan","arguments":{"profile":"local","prepared_directory":"review-001","comment":"Исправление проверки"}}
```

Проверь `ready`, покажи пользователю изменения и получи одобрение возвращённого
`plan_sha256`. Затем передай точные `plan_file` и этот хеш:

```json
{"name":"crs_changes_commit","arguments":{"profile":"local","plan_file":"C:/work/private/.crs-operations/plans/PLAN/plan.json","approved_plan_sha256":"SHA256_ИЗ_ПЛАНА","execute":true}}
```

При любой неопределённости вызывай `crs_changes_status` с теми же
`plan_file/plan_sha256`. Повторная отправка запрещена. Полный контракт, сведения
о захватах, обновлении основы и ограничении меток — в
[описании помещения](status.md#помещение-через-cli-и-mcp).

| Признак | Что проверить |
| --- | --- |
| Инструменты отсутствуют в чате | Сервер включён, пути существуют, настройки перечитаны; перезапусти клиент |
| `codex mcp list` видит сервер, вызов не работает | Регистрация не доказывает запуск; проверь реальный `crs_connect` |
| `Repository password environment variable is not set` | Переменная есть в процессе MCP, её имя совпадает с профилем; для пустого пароля на Windows используй загрузчик |
| Ошибка профиля | Имя `profile` существует в `repositories`; `lab` не является встроенным профилем |
| `OneScript executable not found` | Исправь абсолютный `runtime.oscript` |
| Ошибка загрузки библиотеки/моста | Выполнена установка зависимостей; `module_path` указывает на каталог библиотек |
| Ошибка авторизации | Адрес, имя хранилища, пользователь и пароль; не печатай секреты в диагностике |
| `ibcmd executable not found` или `representation.status=unavailable` | Путь/версия ibcmd-rs и поддержка объекта; нативное чтение можно проверить отдельно |
| Отказ соединения с TCP-сервером | Хранилище действительно запущено и доступно по адресу; MCP не запускает его |
| Открытый вручную MCP ничего не печатает | Для stdio это нормально: он ждёт JSON-RPC от клиента |
| Долгая подготовка обрывается | Таймаут клиента больше таймаута сервера; по умолчанию сервер ограничен 900 секундами |

Обновляй исходники осознанно, сохраняя локальные изменения, затем перезапускай
MCP-клиент. Для отключения только этого сервера задай `enabled=false` в его секции;
для удаления регистрации — `codex mcp remove crs-api`. Настройки, кэш и рабочие
исходники при этом остаются на диске.

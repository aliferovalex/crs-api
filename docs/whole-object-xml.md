# Сериализация полного файла выгрузки

Основной вход сериализатора — целевой файл объекта, а для объекта с кодом или
интерфейсом — комплект его файлов. UUID и версии берутся из XML и свежего
снимка хранилища; частичные операции оставлены как совместимые адаптеры.
Python работает самостоятельно, Конфигуратор используется только для проверки
результата в лаборатории.

| Объект / операция | До изменения | Теперь |
| --- | --- | --- |
| Справочник / реквизит | Добавление одного реквизита по имени и длине | Полный XML справочника: свойства, весь список строковых реквизитов и ссылки на формы |
| Общий модуль | Замена только внешнего текста | XML описания и полный текст модуля, общий читатель с созданием модуля |
| Свойства корня | Список изменённых XML-значений | Все поддерживаемые целевые значения из полного Configuration.xml; исходный XML используется для контроля |
| Управляемая форма | Интерфейс отдельно от описания | Ext/Form.xml, Module.bsl и необязательный XML описания формы |
| Создание Constant/Catalog/Document/Enum/CommonModule | XML объекта | Уже использовало XML объекта; сохраняется ограниченный проверенный профиль |

```bsl
Пакет = Клиент.ПодготовитьИзменениеСправочникаИзXML(Справочник,
    "C:\\export\\Catalogs\\Справочник.xml", ПутьPython);

Пакет = Клиент.ПодготовитьИзменениеОбщегоМодуляИзXML(Модуль,
    "C:\\export\\CommonModules\\Модуль.xml",
    "C:\\export\\CommonModules\\Модуль\\Ext\\Module.bsl", ПутьPython);

Пакет = Клиент.ПодготовитьИзменениеКонфигурацииИзXML(Корень,
    "C:\\export\\Configuration.xml", "C:\\baseline\\Configuration.xml", ПутьPython);

Пакет = Клиент.ПодготовитьИзменениеФормы(Форма,
    "C:\\export\\Catalogs\\Справочник\\Forms\\Форма\\Ext\\Form.xml",
    "C:\\export\\Catalogs\\Справочник\\Forms\\Форма\\Ext\\Form\\Module.bsl",
    ПутьPython, "C:\\export\\Catalogs\\Справочник\\Forms\\Форма.xml");

Клиент.ЗахватитьОбъект(Объект);
Обновлённый = Клиент.ПоместитьОбъект(Объект, Пакет, "Полный файл выгрузки");
Клиент.ОтменитьЗахватОбъекта(Обновлённый);
```

Каждая подготовка возвращает собственный пакет: не используйте один пакет
с описанием другого объекта. Захват нужен для помещения.

Справочник читается через `catalog_object_xml.convert`. Обязателен `InternalInfo`
с прежними UUID сгенерированных типов. Переименование самого справочника пока
запрещено. Свойства справочника поддерживаются по прежнему профилю: имя, синоним,
комментарий и остальные проверенные значения по умолчанию. Строковые реквизиты
читаются целиком: UUID, имя, синоним, комментарий, длина и стандартные свойства.
UUID существующего реквизита нужно сохранять. Добавление реквизита старым
методом сначала формирует целевой XML всего справочника и использует тот же читатель.
Существующие свойства вне проверенного нативного профиля вызывают ошибку.

Отдельные формы перечисляются ссылками в XML справочника. [Удаление одной формы](delete-form.md) реализовано отдельным пакетом по полному XML родителя. Их создание, удаление
и перестановка требуют отдельных пакетов объектов; здесь сохраняются полный
список и порядок существующих форм. Удаление реквизита при наличии форм пока
отклоняется: проверка всех привязок ещё не реализована. Табличные части и другие
типы реквизитов не поддерживаются. Создание справочника через старый общий
сериализатор по-прежнему ограничено объектом без дочерних объектов.

Общий модуль использует `module_xml` и при создании, и при изменении. XML задаёт
весь поддерживаемый набор свойств. Переименование запрещено, флаги пока ограничены
проверенными значениями профиля. Совместимый метод изменения только текста
строит полное XML-описание текущего модуля перед преобразованием.

У корня поддерживаются Comment, Synonym, Vendor, Version, NamePrefix,
UpdateCatalogAddress. Исходная выгрузка пока обязательна, потому что остальные
свойства Configuration.xml ещё не имеют полного самостоятельного преобразования.
Изменение неподдерживаемых секций отклоняется. Поддерживаемые значения исходного
XML сверяются со снимком **даже если целевое значение не изменилось**; целевой XML
задаёт все поддерживаемые значения, а список различий не используется для записи.
Старый метод изменения одного комментария остаётся совместимым ограниченным входом.
Полностью отказаться от исходного XML корня пока нельзя.

XML описания формы задаёт UUID, имя, синоним, комментарий и проверенные стандартные
свойства. При изменении UUID и имя сохраняются. При создании необязательный последний
параметр `ПутьXMLОписания` у `ПодготовитьСозданиеФормыИзXML` позволяет задать UUID и
свойства из файла; UUID должен быть новым, имя — совпадать с аргументом метода.
Без файла описания создание использует прежние стандартные свойства; изменение
сохраняет существующее описание. Ограничения интерфейса указаны в
[описании преобразователя формы](managed-form-xml.md).

Служебные списки дочерних объектов и связи родителя при создании обновляются
отдельно в пакете: новый объект регистрируется в полном текущем состоянии родителя.
Это требуется протоколом хранилища. Поддержка XML не означает поддержку произвольных
свойств платформы: неизвестные структуры должны получать явную ошибку.

Проверено на 8.5.1.1529: версии 19–21 изменили справочник с существующим реквизитом,
общий модуль и корень, версия 22 — описание существующей формы. Нативные CF-выгрузки,
загрузка в отдельные базы и XML-выгрузки подтвердили значения, сохранность UUID,
всех форм и посторонних объектов. Проверка повторного обновления в GUI не выполнялась.

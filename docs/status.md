# Возможности и ограничения CRS API

Библиотека взаимодействует с хранилищем конфигурации 1С по HTTP и самостоятельно
готовит нативные пакеты из XML-выгрузки Конфигуратора. Получение, захват, отмена
захвата и помещение реализованы. Сериализация поддерживает перечисленные ниже
классы и проверенные свойства; **помещение любого изменения произвольной
конфигурации пока не реализовано**.

## Совместимость и зависимости

- Основная проверенная связка клиента и сервера — **8.5.1.1529**.
- Для ветки 8.5.1 и более ранних версий 8.x выбирается общий профиль `legacy`.
  Это правило выбора, а не подтверждение совместимости с каждой старой версией.
- Для 8.5.4.1878 существует отдельный профиль `modern` с ограниченным покрытием.
  Нельзя переносить на него гарантии сериализации профиля `legacy`.
- Для остальных более новых версий профиль XML-сериализации не определён.
- Для API нужен OneScript с зависимостями проекта, для XML-сериализации — Python
  3.9+ и **v8unpack==1.2.13**. Конфигуратор во время подготовки пакета не запускается.

Зависимости Python устанавливаются из корня проекта в используемый интерпретатор:

```powershell
python -m pip install -r src/Сериализация/requirements.txt
```

Пакет из публичного `opm` может отличаться от этой ветки. Новые возможности
относятся к текущим исходникам форка.

## API хранилища

| Возможность | Состояние |
| --- | --- |
| Подключение, версия сервера, проверка существования хранилища | Реализованы |
| Создание хранилища | Реализовано; загрузка исходной конфигурации из CF/CFE не реализована |
| Пользователи | Список, поиск, создание, изменение, удаление и восстановление реализованы |
| `ПолучитьОписаниеОбъекта(UUID)` | Актуальное описание объекта, включая его версию и владельца |
| `СписокОбъектовВерсии(Номер)` | Описания объектов, изменённых в указанной версии; это не полный список конфигурации |
| `ПолучитьОбъект(Описание)` | Нативное содержимое объекта; не XML-выгрузка Конфигуратора |
| `ПолучитьВнешниеДанныеОбъекта(Описание)` | Чтение внешних потоков объекта, например текста модуля |
| `ПолучитьКлассыМетаданных(Корень)` | Каталог классов из содержимого корня; наличие класса не означает наличие его сериализатора |
| `ЗахватитьОбъект`, `ОтменитьЗахватОбъекта` | Работа с одним существующим объектом, с проверкой состояния на сервере |
| `ПодготовитьПакетИзВыгрузки` | Общий вход создания, изменения и явного удаления в пределах покрытия XML-преобразователей |
| `ПоместитьПакет` | Отправка подготовленного пакета, в том числе нескольких связанных объектов |
| `СписокВерсий` | Метод существует, но успешная работа на основной связке 8.5.1 требует отдельной проверки и исправления обработки ответа |

## Покрытие XML-сериализации

«Создание и изменение» в таблице означают работу **в пределах описанного профиля**,
а не поддержку всех свойств соответствующего класса. Неизвестные структуры и
неподдерживаемые значения отклоняются. UUID существующих объектов сохраняются;
переименование объектов не является общей поддерживаемой операцией.

| Объект | Что работает | Основная граница поддержки |
| --- | --- | --- |
| Конфигурация | Изменение комментария, синонима, поставщика, версии, префикса имён и адреса обновления | Полного преобразования всех свойств корня нет; для поддерживаемого профиля исходный XML не обязателен |
| Константа | Создание; строка, число, булево, дата в `legacy` | Общего изменения и удаления константы нет |
| Справочник | Создание и изменение полного XML с реквизитами, табличными частями, ссылками на формы; создание вместе с формами | Ограниченный профиль свойств и типов; удаление реквизитов при существующих формах ограничено проверкой привязок |
| Документ | Создание и изменение; реквизиты, табличные части, встроенные команды и их модули | Ограниченный профиль свойств и связей |
| Перечисление | Создание и изменение, значения, поддерживаемые представления и цвета | Ссылки на удаляемые значения должны быть устранены; не все свойства платформы сопоставлены |
| Общий модуль | Создание и изменение XML-описания и полного текста модуля | Флаги и свойства ограничены профилем |
| Обработка, отчёт | Создание и изменение свойств, модулей объекта и менеджера; отдельные формы и макеты | Не все свойства и связанные объекты поддерживаются |
| Подсистема | Создание и изменение свойств | Без наполнения состава и вложенных подсистем |
| Роль | Создание и изменение свойств | Сериализации произвольного `Rights.xml` нет |
| Группа команд | Создание и изменение свойств стандартного профиля | Не все варианты представлений и размещения |
| Параметр сеанса | Создание и изменение, скалярный тип | Произвольные составные и ссылочные типы не покрыты |
| HTTP-сервис, Web-сервис | Создание и изменение основных свойств | Без методов, операций, шаблонов URL и XDTO-содержимого |
| Регистр сведений | Создание и изменение независимого непериодического регистра, измерений, ресурсов, реквизитов и модулей | Другие режимы и произвольные типы не покрыты |
| Журнал документов | Создание и изменение свойств и ссылок на существующие документы | Без колонок и форм |
| Регистр накопления | Создание и изменение регистра остатков, встроенных полей и модулей | Для создания нужен целевой XML документа-регистратора; другие режимы не покрыты |
| План счетов | Создание и изменение стандартного профиля и модулей | Без субконто и наполнения |
| Регистр бухгалтерии | Создание и изменение профиля без корреспонденции, ссылки на план счетов, полей и модулей | Для создания нужен XML регистратора; остальные режимы не покрыты |
| Управляемые формы | Создание, изменение и удаление форм справочника, документа, обработки, отчёта и общих форм | Частичное покрытие элементов, свойств, событий и привязок |
| Макеты и общие макеты | Создание, изменение и удаление СКД, двоичных данных и текстового документа | Прочие виды макетов и смена вида существующего макета не поддерживаются |

Поддерживаемые скалярные типы — строка, число, булево и дата с квалификаторами.
Ссылочные типы и значения разрешаются только там, где реализовано соответствующее
правило контекста; общей поддержки всех описаний типов пока нет.

### Формы и модули

Преобразователь читает **весь целевой `Form.xml`**, а не список изменений отдельных
элементов. Создание и изменение используют общие правила. Поддержаны поля ввода,
флажки, надписи, группы, страницы, кнопки, таблицы, картинки-декорации,
переключатели, индикаторы и календарные поля в пределах сопоставленных свойств.
Есть правила оформления, событий, команд, списков выбора и привязок к данным.
Обычные формы и произвольная управляемая форма со всеми свойствами не покрыты.

Для формы автоматически ищется соседний `Ext/Form/Module.bsl`. При наличии файла
берётся весь его текст; изменение только модуля также поддерживается. Отсутствующий
файл при изменении сохраняет существующий модуль, пустой файл очищает его текст.
Для поддерживаемых объектов модули читаются из их папки `Ext` по реестру профилей.

### Макеты

XML-описание макета задаёт его UUID, свойства и вид; содержимое читается рядом:

| Вид макета | Файл содержимого | Преобразование |
| --- | --- | --- |
| `DataCompositionSchema` | `<Макет>/Ext/Template.xml` | Полная СКД, включая поддерживаемые варианты настроек, макеты и оформление; ссылки разрешаются по контексту хранилища |
| `BinaryData` | `<Макет>/Ext/Template.bin` | Двоичные данные сохраняются побайтно |
| `TextDocument` | `<Макет>/Ext/Template.txt` | UTF-8, с сохранением BOM и переносов строк |

Основная СКД отчёта может назначаться ссылкой на его существующий макет.
Табличные документы, HTML и другие виды макетов предстоит подключить.
Для СКД остаются ограничения на несопоставленные типы, картинки и оформление.

### Удаление и связанные объекты

Отдельное удаление реализовано для управляемых форм и поддерживаемых макетов.
Вход — полный целевой XML владельца без удаляемого ребёнка, с явно указанным UUID
удаления. Остальные свойства и дети владельца должны сохраниться. Активные ссылки
на удаляемую форму или макет требуют предварительного изменения.

Удаление произвольного объекта метаданных, каскадное удаление и произвольное
перемещение между владельцами ещё не реализованы. Удаление некоторых встроенных
полей или значений из полного XML является отдельной поддерживаемой операцией
преобразователя и не означает поддержку общего удаления.

Пакет может включать новый объект, изменения владельца и связанные объекты.
Для регистра накопления или бухгалтерии документы-регистраторы передаются через
`СвязанныеXML`. Автоматического сравнения всей папки выгрузки и построения пакета
любого набора изменений пока нет.

## Общий порядок работы

1. Подключиться к хранилищу и подготовить полные целевые файлы выгрузки.
2. Вызвать `ПодготовитьПакетИзВыгрузки(ПутьXML, Настройки, ПутьPython)`.
3. Захватить необходимые существующие объекты из `Пакет.СуществующиеОбъекты`.
4. Отправить пакет через `ПоместитьПакет` и освободить оставшиеся свои захваты,
   используя актуальные описания объектов.

Подготовка сама не выполняет захват или помещение. Она получает свежий контекст
хранилища и проверяет исходные версии; при изменении хранилища пакет нужно
подготовить заново. После неоднозначного ответа помещения сначала следует
проверить состояние сервера, поскольку версия могла уже сохраниться.

```bsl
Клиент = Новый КлиентХранилища(
    "http://localhost/repo/repo.1ccr", "8.5.1.1529");
Клиент.Подключиться("Пользователь", "Пароль", "Хранилище");
Пакет = Клиент.ПодготовитьПакетИзВыгрузки(
    "C:\Export\CommonModules\ОбщийМодуль.xml", Неопределено, "python");
Для Каждого Объект Из Пакет.СуществующиеОбъекты Цикл
    Клиент.ЗахватитьОбъект(Объект);
КонецЦикла;
Результат = Клиент.ПоместитьПакет(Пакет, "Изменение общего модуля");
```

Настройки общего входа:

- `Операция`: `Авто` по умолчанию, `Создание`, `Изменение`, `Удаление`.
- `ИдентификаторРодителя`: UUID владельца нового дочернего объекта, если путь
  не соответствует структуре выгрузки.
- `СвязанныеXML`: массив полных целевых XML связанных документов.
- `ИдентификаторОбъекта`: UUID явно удаляемой формы или макета.
- `ПутьИсходногоXML`: дополнительный исходный XML корня для сценариев проверки
  свойств вне самостоятельного поддерживаемого профиля; не расширяет покрытие.

При `Авто` создание или изменение выбирается по наличию UUID в хранилище.
Удаление всегда задаётся явно. Исчезновение отдельно хранимой формы или макета
из XML владельца при обычном изменении не является командой удаления.

## Устройство и проверка

OneScript отвечает за HTTP API и подготовку контекста. Python читает XML и
сопутствующие файлы, применяет правила сопоставления и строит пакет. `v8unpack`
собирает нативные структуры из подготовленной модели; он не читает XML
Конфигуратора напрямую и не заменяет правила сопоставления.

Общий сборщик пакетов формирует граф, версии, внешние потоки и транспортный
контейнер. Поддерживаемые свойства берутся из полного целевого файла; неизменяемые
структуры и потоки сохраняются из актуального снимка. Это ещё не полностью
самостоятельное восстановление любого объекта только по XML.

Есть автоматические проверки преобразований, пакетов и отказов на неподдерживаемых
структурах. Основные сценарии проверялись помещением в хранилище 8.5.1.1529,
нативной загрузкой CF и сравнением XML/потоков с результатом Конфигуратора.
Такая проверка подтверждает конкретные сценарии, а не всё содержимое класса.
Для двоичных и текстовых макетов нативное создание и изменение проверены на общих
макетах; макеты владельцев подключены к тому же механизму, но не все сочетания
видов и владельцев отдельно проверены на сервере.

Алгоритм нативного идентификатора версии полностью не восстановлен: используемый
UUID + CRC32 остаётся экспериментальным. Универсальная совместимость с платформой
и промышленная готовность всех преобразователей пока не подтверждены.

## Что предстоит сделать

1. Завершить сопоставление свойств, типов, ссылок и сопутствующих файлов уже
   подключённых классов. Расширить формы и виды макетов.
2. Подключить остальные классы: общие команды и реквизиты, функциональные опции,
   регламентные задания, определяемые типы, хранилища настроек, планы обмена,
   планы видов характеристик и расчёта, регистры расчёта, задачи, бизнес-процессы,
   XDTO и другие пока отсутствующие профили.
3. Реализовать общее удаление, переименование и перемещение с проверкой зависимостей.
4. Добавить сравнение всей выгрузки с хранилищем и сборку единого пакета связанных
   созданий, изменений и удалений.
5. Восстановить алгоритм нативных версий, исправить получение истории версий и
   расширить проверки совместимости за пределы основной сборки 8.5.1.1529.

Критерий завершения — возможность поместить произвольный поддерживаемый платформой
набор изменений конфигурации без ручного формирования нативных пакетов и потери
свойств. Текущее покрытие до этого критерия ещё не дошло.

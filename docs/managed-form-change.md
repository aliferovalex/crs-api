# Изменение существующей формы

Для загрузки всего `Form.xml` и модуля используйте [общий преобразователь](managed-form-xml.md).
Метод ниже сохранён как совместимый адаптер к нему.

`ПодготовитьПолеРеквизитаНаФорме(Форма, ИмяРеквизита, ПутьPython = "python")`
возвращает `ПакетИзмененияФормы`.
`ПоместитьИзменениеФормы(Форма, Пакет, Комментарий, ИдентификаторПодключения)`
помещает изменение и возвращает актуальное описание той же формы.

```bsl
Форма = Клиент.ПолучитьОписаниеОбъекта(UUIDФормы);
Пакет = Клиент.ПодготовитьПолеРеквизитаНаФорме(Форма,
    "CRSAPI_TestAttribute", "C:\Program Files\Python39\python.exe");
Клиент.ЗахватитьОбъект(Форма);
Обновлённая = Клиент.ПоместитьИзменениеФормы(Форма, Пакет,
    "Поле существующего реквизита");
Клиент.ОтменитьЗахватОбъекта(Обновлённая);
```

Имя относится к уже существующему строковому реквизиту родительского справочника.
Метод находит его UUID в текущем теле справочника и добавляет поле ввода с таким же
именем. Привязка — `Object.ИмяРеквизита`. Сохраняются UUID формы, её свойства,
основной реквизит, прежние элементы и модуль формы. Меняется внешний поток интерфейса.
Захват родительского справочника не требуется; захват формы сохраняется после помещения.

Текущие данные берутся по HTTP из `DevDepot_devObjectsVersionEx`, а не из встроенного
образца интерфейса. Проверяются версии формы, исходного внешнего потока и хранилища,
класс и тип основного реквизита, наличие реквизита и отсутствие поля с тем же именем
или привязкой. Пакет после изменения хранилища следует подготовить заново.

`ПолучитьВнешниеДанныеОбъекта(Объект, ПутьPython)` позволяет отдельно прочитать
внешние потоки. Возвращает структуру `object_id`, `class_id`, `parent_id`,
`version_number`, `original`, `local`, `data`, `externals`. Первые 32 hex-символа
версий объекта представлены в `original`/`local`; `data` — Base64 тела объекта,
сжатого raw DEFLATE. Каждый элемент `externals` содержит `name`, `version` (40 hex)
и `data` (Base64 сжатого внешнего потока). Чтение проверяет актуальность описания.

Пакет полной версии может содержать физически повторяющиеся записи. Читатель
проверяет обе SHA1-контрольные суммы, индекс каждой физической записи, манифест
объектов и соответствие внешних версий. Одинаковое содержимое разрешается только
при наличии корректных отдельных записей индекса. Индексы одиночных снимков
по-прежнему проверяются прежним строгим валидатором.

Границы: проверенные управляемые формы справочника с одним основным `Object` и
плоскими полями ввода. Добавляется поле существующего строкового реквизита;
произвольная XML-разметка, группы, таблицы, другие типы реквизитов и создание
обработчика пока не реализованы. Сам реквизит должен быть создан заранее.
Для извлечения потока читается пакет всей текущей конфигурации; предел — 16 МиБ
двоичного хранилища, поэтому это пока не оптимизировано для крупных конфигураций.

Профиль legacy, Python 3.9+ со стандартной библиотекой. Проверено на 8.5.1.1529;
выпуски старше по возрасту отдельно не проверялись. Библиотека не запускает
Конфигуратор. Алгоритм внутренних UUID версий остаётся экспериментальным.

В версии 16 в `CRSAPI_TestCatalogForm` добавлено поле `CRSAPI_TestAttribute`.
Нативная CF-выгрузка, загрузка в отдельную базу и XML-выгрузка подтвердили привязку
`Object.CRSAPI_TestAttribute`, сохранность полей Code/Description и UUID формы.
Свойства формы и остальные объекты, включая вторую форму и общий модуль, не изменились.

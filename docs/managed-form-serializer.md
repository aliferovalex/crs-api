# Управляемые формы

Общий сериализатор `managed_form_serializer.py` поддерживает три проверенных вида
форм. Он создаёт новый объект формы и согласованное изменение её родителя.

| Вид | Родитель | Реквизиты и поля шаблона |
| --- | --- | --- |
| Форма справочника | Описание справочника | Основной `Object`, `Object.Code`, `Object.Description` |
| Форма документа | Описание документа | Основной `Object`, `Object.Number`, `Object.Date` |
| Общая форма | Описание корня конфигурации | `Message`: строка длины 100, поле ввода `Message` |

Параметры методов подготовки: описание родителя, имя формы, путь к Python.
Имя по умолчанию — `ФормаЭлемента`, `ФормаДокумента` или `ОбщаяФорма` соответственно.

```bsl
Документ = Клиент.ПолучитьОписаниеОбъекта(UUIDДокумента);
Пакет = Клиент.ПодготовитьСозданиеФормыДокумента(Документ,
    "ФормаДокумента", "C:\Program Files\Python39\python.exe");
Клиент.ЗахватитьОбъект(Документ);
Форма = Клиент.ПоместитьСозданиеФормыДокумента(Пакет, "Форма документа");
Клиент.ОтменитьЗахватОбъекта(Клиент.ПолучитьОписаниеОбъекта(UUIDДокумента));
Клиент.ОтменитьЗахватОбъекта(Форма);

Корень = Клиент.ПолучитьОписаниеОбъекта(UUIDКорня);
Пакет = Клиент.ПодготовитьСозданиеОбщейФормы(Корень,
    "ОбщаяФорма", "C:\Program Files\Python39\python.exe");
Клиент.ЗахватитьОбъект(Корень);
Форма = Клиент.ПоместитьСозданиеОбщейФормы(Пакет, "Общая форма");
Клиент.ОтменитьЗахватОбъекта(Клиент.ПолучитьОписаниеОбъекта(UUIDКорня));
Клиент.ОтменитьЗахватОбъекта(Форма);
```

Методы возвращают `ПакетСозданияФормыДокумента` или `ПакетСозданияОбщейФормы`;
методы помещения возвращают описание нового объекта. Для справочника остаются
прежние методы и `ПакетСозданияФормыСправочника`.

Можно добавлять следующие формы. Проверяются уникальность имени без учёта регистра,
карта существующих форм и её соответствие нативному телу родителя. UUID и порядок
существующих форм сохраняются; новые формы добавляются в конец коллекции. Карта
дочерних объектов берётся из `updateInfo`: снимок получения может не содержать её.
Для общей формы сохраняются остальные классы, связи и признаки корня конфигурации.

Перед помещением требуется захват родителя текущим пользователем. Проверяются
актуальность объекта и версии хранилища, исходная версия, описание, класс родителя
и имя внешнего потока. Помещение сохраняет захваты, их освобождение показано выше.
Другие объекты не пересылаются и их внешние данные не заменяются.

Границы поддержки: управляемые формы указанных трёх видов и их стандартные шаблоны.
Справочник должен иметь строковый код 9 и наименование 25; документ — проверенную
структуру и номер длины 9. Дочерними объектами справочника/документа пока могут быть
только формы. Произвольный XML интерфейса, модуль формы, другие реквизиты и элементы,
обычные формы, формы других классов пока не реализованы. Добавление поля существующего реквизита описано в
[методе изменения формы](managed-form-change.md).
Формы не назначаются основными автоматически. Методы создания объектов верхнего
уровня из XML по-прежнему ограничены конфигурациями без вложенных объектов.

Используется профиль legacy и Python 3.9+ со стандартной библиотекой. Нативная
проверка выполнена на 8.5.1.1529. Старые 8.x выбирают тот же профиль, но каждый
выпуск отдельно не проверялся; неизвестная структура отвергается. Нативные шаблоны
хранятся в отдельных JSON, UUID класса читаются через `metadata_identifiers`.
При работе библиотеки Конфигуратор не запускается. Алгоритм UUID версий экспериментальный.

Проверено в лаборатории: форма документа — версия 12, общая форма — 13, вторая
форма справочника — 14. Нативная CF-выгрузка, загрузка в отдельную базу и последующая
XML-выгрузка подтвердили интерфейсы, привязки и типы реквизитов. Первая форма
справочника и текст общего модуля сохранились.

# Создание справочника из XML

Экспериментальные методы для **8.5.1.1529**:

* `ПодготовитьСозданиеСправочникаИзXML(Корень, XMLСправочника, ПутьPython)`;
* `ПоместитьСозданиеСправочника(Пакет, Комментарий, ИдентификаторПодключения)`.

Первый метод возвращает `ПакетСозданияСправочника`; UUID нового объекта доступен
в `Пакет.ИдентификаторОбъекта`. Второй возвращает его актуальное описание.
Для подготовки используются свежий контекст хранилища и снимки всех объектов;
Конфигуратор и записанный запрос помещения не нужны. Требуется Python 3.9+.

Передаётся текст `Catalogs/Имя.xml` с версией XML `2.21` (атрибут версии можно
опустить). Поддержан справочник с обычными свойствами: код — строка длины 9,
наименование — длины 25, без иерархии, владельцев, новых реквизитов, табличных
частей, форм, команд, макетов и внешних данных. Имя, синоним и комментарий
задаются в XML; остальные явно указанные свойства должны совпадать с проверенными
значениями по умолчанию. Изменённые неподдерживаемые свойства отклоняются.
Содержимое модулей, справки и предопределённых данных этим методом не принимается.

UUID должен быть новым, имя — отсутствовать среди справочников хранилища.
Пять `InternalInfo/GeneratedType` читаются из XML; при отсутствии `InternalInfo`
генерируются десять новых UUID типов. Дубликаты и пересечения с существующими
идентификаторами отклоняются. Пример минимального XML:

```xml
<MetaDataObject xmlns="http://v8.1c.ru/8.3/MDClasses" version="2.21">
  <Catalog uuid="11111111-2222-4333-8444-555555555555">
    <Properties>
      <Name>XML_Catalog</Name>
      <Comment>Создан из XML</Comment>
    </Properties>
    <ChildObjects/>
  </Catalog>
</MetaDataObject>
```

```bsl
Корень = Клиент.ПолучитьОписаниеОбъекта(UUIDКорня);
Пакет = Клиент.ПодготовитьСозданиеСправочникаИзXML(Корень,
    XMLСправочника, "C:\Program Files\Python39\python.exe");
Для Каждого Объект Из Пакет.СуществующиеОбъекты Цикл
    Клиент.ЗахватитьОбъект(Объект);
КонецЦикла;
Справочник = Клиент.ПоместитьСозданиеСправочника(Пакет, "Справочник из XML");
```

Помещение требует захват всех исходных объектов текущим пользователем и сохраняет
захваты. Если корень уже захвачен в Конфигураторе, повторно захватывать его не нужно.
После успешной проверки освободите захваты методом `ОтменитьЗахватОбъекта`, передав
свежие описания объектов, включая новый справочник. При ошибке отправки сначала
проверьте историю: автоматический повтор может создать лишнюю версию.

Конфигурация должна быть плоской: языки, строковые константы и простые справочники,
без вложенных или внешних данных. Шаблон проверенного тела и значения свойств
вынесены в `catalog_layout_851.json`; построение выполняет `catalog_serializer.py`.
Граф создания, снимки, проверки актуальности и владельца захвата используются
совместно с сериализатором констант. В нативном запросе создания справочника
признаки корня и нового объекта пустые: признак изменения коллекции констант
для справочника не передаётся.

Проверка в `ManualClean8511529Lab`: `CRSAPI_TestCatalog` создан из XML библиотекой,
версия 5 → 6; тело размером 1404 байта совпало побайтно с нативным пакетом,
выгрузкой CF и последующим получением с сервера. Захваты освобождены. Пользователь
подтвердил, что повторное обновление в Конфигураторе не получает объекты снова.

Генерация UUID/CRC версий остаётся экспериментальной: алгоритм нативного хеша
версии не восстановлен. Поддержка других сборок и произвольных свойств не заявлена.

# Удаление формы справочника

```bsl
Форма = Клиент.ПолучитьОписаниеОбъекта(UUIDФормы);
Родитель = Клиент.ПолучитьОписаниеОбъекта(Форма.ИдентификаторРодителя);
Пакет = Клиент.ПодготовитьУдалениеФормы(Форма,
    "C:\export\Catalogs\Справочник.xml", ПутьPython);
Клиент.ЗахватитьОбъект(Родитель);
Клиент.ЗахватитьОбъект(Форма);
ОбновлённыйРодитель = Клиент.ПоместитьУдалениеФормы(Пакет, "Удаление формы");
Клиент.ОтменитьЗахватОбъекта(ОбновлённыйРодитель);
```

Вход — **полный целевой XML родительского справочника**, в котором из
`ChildObjects` убрана ровно одна ссылка `Form` с именем удаляемой формы.
Свойства справочника, реквизиты и остальные формы должны сохраниться без
изменений. Используется общий читатель полного XML справочника.

В пакете меняется полное тело и список дочерних объектов родителя. Форма
передаётся отдельно в `objectsToRemove` с её исходным описанием и фактической
версией. Граф отмечает её как неактивную; новое тело удалённой формы и её
внешний поток не отправляются. Исходные связи графа берутся из актуального
контекста хранилища. Остальные объекты перечисляются без изменений версий.

Подготовка проверяет UUID, классы, родителя, снимки обоих объектов, исходные
версии и актуальность хранилища. Помещение требует захвата формы и родителя
текущим пользователем. После ответа проверяются новая версия родителя и
отсутствие формы среди активных объектов. Захват родителя сохраняется; его
нужно освободить после операции. Уже захваченные объекты повторно захватывать
не требуется. Не повторяйте помещение автоматически после ошибки: сначала
проверьте состояние хранилища и подготовьте свежий пакет.

Первый профиль: один `CatalogForm`, legacy, Python 3.9+ со стандартной
библиотекой. Ограничения свойств родителя те же, что у
[читателя полного XML](whole-object-xml.md). В частности, назначенные формы
по умолчанию, табличные части и другие неподдерживаемые свойства отклоняются.
Удаление форм документов, общих форм, нескольких форм одним пакетом и
произвольных объектов ещё не реализовано.

Проверено на 8.5.1.1529: сначала на отдельной копии хранилища, затем в основной
лаборатории. Версия **23** удалила `CRSAPI_XMLWholeForm`
(`4b980765-c589-4b00-9d38-1291d756edbe`). Нативная CF-выгрузка подтвердила
отсутствие объекта и его `.0` потока; все остальные тела и внешние потоки
сохранились, кроме нового списка форм справочника и служебных версий.
Загрузка CF в отдельную базу и XML-выгрузка подтвердили две оставшиеся формы:
`CRSAPI_TestCatalogForm` и `CRSAPI_TestCatalogFormSecond`.

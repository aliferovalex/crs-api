# Создание управляемой формы справочника

`ПодготовитьСозданиеФормыСправочника(Справочник, ИмяФормы = "ФормаЭлемента", ПутьPython = "python")`
возвращает `ПакетСозданияФормыСправочника`.
`ПоместитьСозданиеФормыСправочника(Пакет, Комментарий, ИдентификаторПодключения)`
помещает форму и возвращает описание созданного объекта.

Это генератор проверенного шаблона формы элемента: основной реквизит `Object`
типа `CatalogObject` данного справочника, поля `Code` и `Description` с привязками
`Object.Code` и `Object.Description`, автоматическая командная панель. Метод
создаёт интерфейс формы, но не назначает её основной формой справочника.
Имя формы проверяется как идентификатор 1С длиной до 80 символов; UUID генерируется.

```bsl
Справочник = Клиент.ПолучитьОписаниеОбъекта(UUIDСправочника);
Пакет = Клиент.ПодготовитьСозданиеФормыСправочника(Справочник,
    "ФормаЭлемента", "C:\Program Files\Python39\python.exe");
Клиент.ЗахватитьОбъект(Справочник);
Форма = Клиент.ПоместитьСозданиеФормыСправочника(Пакет,
    "Управляемая форма справочника");
Клиент.ОтменитьЗахватОбъекта(Клиент.ПолучитьОписаниеОбъекта(UUIDСправочника));
Клиент.ОтменитьЗахватОбъекта(Форма);
```

Пакет содержит только новый объект формы и изменение справочника. Обновляются
нативная коллекция форм в теле справочника, карта дочерних классов и внешние данные
интерфейса `UUIDФормы.0`. UUID типа основного реквизита читается из свежего тела
справочника. Корень конфигурации и остальные объекты не пересылаются.

Перед помещением нужно захватить справочник текущим пользователем. Проверяются
актуальность снимка, версии объекта и хранилища, владелец захвата и отсутствие
нового UUID. Захваты сохраняются, в примере они освобождаются явно.

Поддержан справочник без внешних потоков, с проверенной
нативной структурой, строковым кодом длины 9 и наименованием длины 25. Можно создавать несколько форм: карта и порядок существующих форм сохраняются,
повтор имени без учёта регистра отклоняется. Другие дочерние объекты пока не поддержаны. Произвольные
XML-разметки, дополнительные реквизиты, модуль формы, обычные формы и изменение
существующей формы пока не реализованы. Другие методы создания объектов верхнего
уровня по XML по-прежнему требуют конфигурацию без вложенных объектов; наличие
формы справочника выходит за текущие границы этих методов.

Используется [профиль legacy](platform-compatibility.md), проверен выпуск 8.5.1.1529.
Более ранние 8.x выбирают тот же профиль; несовместимая нативная структура
отклоняется до помещения. Требуется Python 3.9+ со стандартной библиотекой.
Шаблон получен нативным Конфигуратором; при вызове методов библиотека формирует
пакет самостоятельно, без запуска платформы и без воспроизведения записанного RPC.
Внутренний алгоритм UUID версий остаётся экспериментальным.

В лаборатории `CRSAPI_TestCatalogForm` создана в версии 11. Проверены нативная
CF-выгрузка, загрузка CF в отдельную базу и XML-выгрузка формы. Обе привязки полей
и тип основного реквизита подтвердились; остальные объекты конфигурации, включая
текст общего модуля, сохранились.

Общая сборка пакетов вынесена в `managed_form_serializer.py`.
[Формы документов и общие формы](managed-form-serializer.md) используют тот же механизм.

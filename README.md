## Краткое описание

Библиотека позволяет напрямую взаимодействовать с сервером хранилища 1С по протоколу HTTP. 
В библиотеке не используется пакетный режим запуска 1С.

## Область применения

Библиотека используется для централизованного управления хранилищами 1С. С помощью проекта например можно:
* Управлять пользователями хранилищ в едином месте.

P.S. Для этого требуется написать веб приложение на базе [OneScript.Web](https://github.com/EvilBeaver/OneScript.Web).

## Установка

### С помощью `opm`

В консоли нужно выполнить команду:
```sh
opm install crs-api
```

### Из файла

Собираем вручную или качаем пакет из раздела `Релизы`. Для установки из файла, в консоли выполняем команду:
```sh
opm install -f /path/to/crs-api.osxp
```

## Примеры

### Версия сервера хранилищ 1С

Для запроса версии сервера хранилищ 1С:
```bsl
АдресХранилища = "http://localhost/repo/repo.1cc";
ВерсияСервераХранилища = МенеджерХранилищ.ВерсияСервераХранилища(АдресХранилища);
```

После выполнения, `ВерсияСервераХранилища` содержит версию сервера хранилища. Например: `8.3.12.1855`.
В случае возникновения будет вызвано исключение.

### Проверка существования хранилища 1С

Для проверки существования хранилища 1С:
```bsl
АдресХранилища = "http://localhost/repo/repo.1ccr";
ИмяХранилища = "MyTrade";
ВерсияПлатформы = "8.3.15.1855";
ХранилищеСуществует = МенеджерХранилищ.ХранилищеСуществует(АдресХранилища, ИмяХранилища, ВерсияПлатформы);
```

Если хранилище существует, то значение переменной `ХранилищеСуществует` будет `Истина`.

### Создание нового хранилища 1С

Для создания нового хранилища 1С требуется:
* Сервер хранилищ 1С опубликованный на веб-сервере

```bsl
АдресХранилища = "http://localhost/repo/repo.1ccr";
ИмяХранилища = "MyTrade";
ВерсияПлатформы = "8.3.15.1855";
Пользователь = "Администратор";
Пароль = "qwerty12345";
Результат = МенеджерХранилищ.НовоеХранилище1C(АдресХранилища, ИмяХранилища, 
    ВерсияПлатформы, Пользователь, Пароль);	

Сообщить(Результат); // ИмяХранилища
```

В результате на сервере хранилищ 1С будет создано новое хранилище 1С с именем `MyTrade`. 
Хранилище будет доступно по адресу: `http://localhost/repo/repo.1ccr/MyTrade`. 
Если хранилище не было создано, `Результат` будет равен `Неопределено`.

### Подключение к хранилищу 1С

```bsl
АдресХранилища = "http://localhost/repo/repo.1ccr";
ВерсияПлатформы = "8.3.15.1855";
ИмяХранилища = "MyTrade";
Пользователь = "Администратор";
Пароль = "qwerty12345";

КлиентХранилища = Новый КлиентХранилища(АдресХранилища, ВерсияПлатформы);
КлиентХранилища.Подключиться(Пользователь, Пароль, ИмяХранилища);
```

В результате с помощью `КлиентХранилища` теперь можно будет выполнять основное взаимодействие с хранилищем.
При ошибке подключения (сервер хранилища недоступен) будет вызвано исключение. При успешном подключении:
```bsl
// ...
КлиентПодключен = КлиентХранилища.АвторизацияПройдена(); // КлиентПодключен будет равен Истина при успешном подключении
```

### Получение актуального описания по UUID

```bsl
// UUID можно взять из атрибута uuid в XML-выгрузке объекта.
Объект = КлиентХранилища.ПолучитьОписаниеОбъекта(
    "e2a9c158-4b91-424a-b10d-07b43280ce83");
```

Метод принимает строку UUID или `УникальныйИдентификатор`, возвращает полный
актуальный `ОбъектХранилища`: UUID, класс, имя, позицию, версии, родителя и
владельца. Полученное описание подходит для получения снимка, захвата, отмены
захвата и подготовки пакета помещения. Перед вызовом необходимо подключиться.

Сначала библиотека узнаёт последнюю версию самого объекта через
`DevDepot_devObjectsStatistic`, получает его описание через
`DevDepot_versionObjects` и повторно проверяет номер версии. Объект не обязан
входить в изменения последней версии хранилища. Номер версии заранее знать
не требуется; перебор всей истории не выполняется. Метод только читает данные.

Некорректный/нулевой UUID, отсутствующий или удалённый объект, неполное описание,
ошибка сервера и изменение версии объекта во время чтения вызывают исключение.
После получения описание может устареть: операции захвата, получения и помещения
снова проверяют актуальность. Сохранённый отдельно дескриптор можно обновить
повторным вызовом этого метода по UUID.

Проверки без сервера: `oscript tests/check-object-description.os`.
Интеграционная проверка: `oscript tests/integration-object-description.os
<repository.json> <developer.json>`. На ProtocolLab проверены корень версии 7,
язык версии 1, отсутствующий в последних изменениях, получение снимков и
неизвестный UUID. Хранилище при проверке не изменяется.

### Получение объекта хранилища

После подключения можно получить актуальный снимок одного объекта:

```bsl
Объект = КлиентХранилища.ПолучитьОписаниеОбъекта(ИдентификаторИскомогоОбъекта);
Снимок = КлиентХранилища.ПолучитьОбъект(Объект);
Снимок.Данные.Записать("object.deflate");
Снимок.ПакетСнимков.Записать("object.snapshot.bin");
```

Метод возвращает `СнимокОбъектаХранилища`:

* `Объект` — переданное описание объекта.
* `Данные` — бинарное содержимое объекта, сжатое raw DEFLATE.
* `Метаданные` — строка описания снимка в сериализации сервера.
* `ПакетСнимков` — полный бинарный пакет `snapshots/data`, включая дополнительные разделы.
* `ВерсияХранилища` — UUID версии хранилища, использованный при запросе.

Содержимое использует внутренний формат 1С; для формирования `.cf` или загрузки в
рабочую конфигурацию потребуется отдельная обработка. Метод получает один объект
без дочерних объектов, не захватывает его и не меняет рабочую конфигурацию.
Устаревшее описание, отсутствующий или удалённый объект, неполный ответ и
несоответствие UUID, класса или версии снимка приводят к исключению.
Получение исторических версий этим методом не поддерживается.

Проверено на сервере **8.5.4.1878** для корня конфигурации и языка.
Разбор бинарного пакета зависит от внутреннего протокола этой версии платформы;
другие версии и типы объектов требуют проверки. Требуется **OneScript 1.8.2+**.

Для проверки без сервера: `oscript tests/check-get-object.os`.
Интеграционный тест `tests/integration-get-object.os` использует локальный стенд
ProtocolLab и принимает JSON настроек хранилища, JSON учётных данных разработчика
и каталог для снимков. Он проверяет содержимое корня и языка, неизменность
состояния захвата и отказ при устаревшем описании или отсутствующем объекте.

### Захват объекта хранилища

После подключения можно захватить один существующий объект без его дочерних объектов:

```bsl
// Номер версии, в которой объект был последний раз изменен.
ОбъектыВерсии = КлиентХранилища.СписокОбъектовВерсии(НомерВерсии);
Для Каждого Объект Из ОбъектыВерсии Цикл
    Если Объект.Идентификатор = Строка(ИдентификаторИскомогоОбъекта) Тогда
        КлиентХранилища.ЗахватитьОбъект(Объект);
        Прервать;
    КонецЕсли;
КонецЦикла;
```

`СписокОбъектовВерсии` возвращает массив `ОбъектХранилища` с описаниями изменений
указанной версии, а не полный состав конфигурации. На проверенной платформе
8.5.4.1878 номер `0` соответствует последней версии. Если объект в этой версии
не менялся, получите его актуальное описание через `ПолучитьОписаниеОбъекта(UUID)`
или укажите версию его последнего изменения.

`ЗахватитьОбъект(Объект, ИдентификаторПодключения = Неопределено)` возвращает
`Истина` после проверки владельца захвата. При отсутствии авторизации, устаревшем
описании, захвате другим пользователем или ошибке сервера вызывает исключение.
Выполнение запроса не получает содержимое объекта и не обновляет рабочую конфигурацию.

Сервер требует полное описание объекта: UUID, UUID класса, имя, позицию, номера
версий, UUID родителя и владельца, исходную и локальную контрольные суммы,
признак удаления. Они представлены свойствами `ОбъектХранилища`:
`Идентификатор`, `ИдентификаторКласса`, `Имя`, `Позиция`, `НомерВерсии`,
`НомерСобственнойВерсии`, `ИдентификаторРодителя`, `ИдентификаторВладельца`,
`ИсходнаяВерсия`, `ЛокальнаяВерсия`, `Удален`. Контрольные суммы передаются
в виде строк из 40 шестнадцатеричных символов, как в ответе сервера.

По умолчанию `bindID` принадлежит экземпляру клиента. При необходимости можно
передать явный UUID привязки вторым аргументом. Проверено на сервере 8.5.4.1878;
совместимость с другими версиями платформы требует отдельной проверки.

Локальные проверки: `oscript tests/check-capture-object.os`. Интеграционная
проверка для нашего стенда: `oscript tests/integration-capture-object.os
<admin.json> <developer.json>`; первый JSON содержит `Repository`, `User`,
`Password`, второй — `User`, `Password`. Проверка использует опубликованное
тестовое хранилище на `http://127.0.0.1:18088/repo/repo.1ccr`, захватывает
свободный объект последней версии и освобождает его после теста. Файлы с паролями
хранятся вне репозитория.

### Помещение объекта в хранилище

```bsl
// XML нативного запроса DevDepot_commitObjects, подготовленного Конфигуратором
// и сохранённого до его отправки серверу.
Чтение = Новый ЧтениеТекста("commit-request.xml", КодировкаТекста.UTF8);
ТекстЗапроса = Чтение.Прочитать();
Чтение.Закрыть();
Пакет = Новый ПакетПомещенияОбъекта;
Пакет.ЗаполнитьИзЗапроса(ТекстЗапроса);

// Объект — актуальное описание из СписокОбъектовВерсии.
// Если пакет получен от подключённого Конфигуратора, передайте bindID его запроса.
НовыйОбъект = КлиентХранилища.ПоместитьОбъект(Объект, Пакет,
    "Изменение комментария", ИдентификаторПодключения);
```

Метод отправляет **готовый нативный пакет** одного существующего объекта.
Создание новой константы проверено отдельно с пакетом Конфигуратора;
[результат эксперимента и ограничения](docs/constant-creation-experiment.md).
Бинарный снимок из `ПолучитьОбъект`, файл `.cf` или изменённые файлы конфигурации
сами по себе не являются пакетом помещения. Для изменения свойств корня
реализован экспериментальный сериализатор, описанный ниже. Формирование пакета
для произвольных изменений пока не реализовано: пакет содержит граф конфигурации,
связи, сериализованные данные объекта и контрольные суммы.

`ПакетПомещенияОбъекта.ЗаполнитьИзЗапроса` извлекает данные, исходную и локальную
версии, UUID версии хранилища и особенности помещения. Авторизация из исходного
запроса не переносится: применяется учётная запись подключённого клиента библиотеки.
Поддерживаются запросы ровно для одного объекта, без удаления, внешних изменений
и непустого `code`. Используйте пакет, подготовленный для этого хранилища и версии
платформы. Библиотека проверяет XML-конверт и заголовок бинарного пакета;
полное содержимое сжатого графа обрабатывает сервер 1С.

Перед отправкой метод проверяет актуальность описания, исходную версию пакета,
владельца захвата и UUID текущей версии хранилища. После отправки проверяет
ошибки сервера, появление новой версии объекта и совпадение её UUID с локальной
версией нативного пакета. Возвращает новое описание `ОбъектХранилища`.
На 8.5.4.1878 код `6` с пустым списком объектов в `unprocessed` наблюдался при
успешном помещении; он допускается только с последующей проверкой новой версии.
Остальные необработанные результаты приводят к исключению.

Метод не вызывает отмену захвата; на тестовом стенде захват сохранялся после
помещения. При необходимости вызовите `ОтменитьЗахватОбъекта(НовыйОбъект)`.
Если после отправки запроса возникла ошибка связи или проверки результата,
помещение могло уже выполниться. Проверьте состояние и историю хранилища перед
следующей попыткой. Автоматический повтор не выполняется.

Проверено на **8.5.4.1878** для изменения комментария корня конфигурации:
новая версия повторно получена и её содержимое проверено. Другие типы объектов
и версии платформы требуют проверки.
Проверки без сервера: `oscript tests/check-put-object.os`.
`tests/integration-put-object.os` принимает JSON владельца захвата, JSON другого
пользователя, путь к ещё не отправленному запросу и каталог для результата.
Он создаёт одну версию в локальном ProtocolLab и проверяет чужой захват,
устаревшее описание, новую версию, её UUID, повторное получение и запрет
повторного использования пакета.
После подтверждения результата тест снимает захват своего объекта.

### Формирование нативного пакета из XML

`ПодготовитьСвойстваИзXML` создаёт `ПакетПомещенияОбъекта` для изменения
свойств существующего корня на **8.5.1.1529 и 8.5.4.1878**. Поддерживаются:

| XML-свойство | Свойство конфигурации |
| --- | --- |
| `Comment` | Комментарий |
| `Synonym` | Синоним, в том числе несколько языков |
| `NamePrefix` | Префикс имени |
| `Vendor` | Поставщик |
| `Version` | Версия |
| `UpdateCatalogAddress` | Адрес каталога обновлений |

Можно изменить одно или несколько поддерживаемых свойств за одно помещение.
`ПодготовитьКомментарийИзXML` сохранён и по-прежнему разрешает только `Comment`.
Нужен **Python 3.9+**, дополнительные Python-пакеты не нужны. Конфигуратор
при формировании пакета не запускается; сохранённый запрос помещения не нужен.

```bsl
// UUID корня — из атрибута Configuration/@uuid в XML-выгрузке.
Объект = КлиентХранилища.ПолучитьОписаниеОбъекта(UUIDКорня);
// Передайте содержимое Configuration.xml до и после редактирования свойств.
Чтение = Новый ЧтениеТекста("before/Configuration.xml", КодировкаТекста.UTF8);
ИсходныйXML = Чтение.Прочитать();
Чтение.Закрыть();
Чтение = Новый ЧтениеТекста("after/Configuration.xml", КодировкаТекста.UTF8);
ИзмененныйXML = Чтение.Прочитать();
Чтение.Закрыть();

Пакет = КлиентХранилища.ПодготовитьСвойстваИзXML(Объект,
    ИсходныйXML, ИзмененныйXML, "C:\Program Files\Python39\python.exe");
// Подготовка только читает хранилище. Помещение требует собственного захвата.
КлиентХранилища.ЗахватитьОбъект(Объект);
НовыйОбъект = КлиентХранилища.ПоместитьОбъект(Объект, Пакет, "Свойства из XML");
КлиентХранилища.ОтменитьЗахватОбъекта(НовыйОбъект);
```

Путь к Python можно не передавать, если команда `python` доступна в PATH.
Обе XML-выгрузки должны содержать одинаковые UUID и имя конфигурации. Исходное
значение каждого изменяемого свойства должно совпадать с текущим снимком сервера.
Изменения остальных XML-свойств, отсутствие изменений, внешние данные и другие версии платформы
отклоняются. Изменения в отдельных файлах выгрузки этим методом не обрабатываются.

Библиотека получает свежие данные через `ПолучитьОбъект` и `DevDepot_updateInfo`,
проверяет согласованность версий, сохраняет остальные байты объекта и его связи,
строит граф помещения, индекс SHA1 и контрольные суммы контейнера, затем сжимает
пакет raw DEFLATE. Повреждённые контейнеры отклоняются до подготовки пакета.
Новая локальная версия формируется как UUID с CRC32 содержимого; внутренний
алгоритм генерации версии Конфигуратора не восстановлен. Это экспериментальная
реализация внутреннего протокола, пока проверенная на перечисленных свойствах корня.
Эти методы не создают объекты: нужны существующий серверный снимок и два состояния
XML. Для создания строковой константы есть отдельный экспериментальный метод ниже.

На локальном стенде библиотека создала версию 6 из самостоятельно сформированного
пакета. Результат повторно получен через API, выгружен Конфигуратором в `.cf`,
загружен в отдельную базу и выгружен в XML: комментарий и UUID языка подтверждены.
Подготовка пакета также проверена на полном `Configuration.xml` из этой выгрузки.
Для проверки остальных свойств значения-маркеры загружены Конфигуратором из XML
в отдельную базу, а их позиции установлены по нативной выгрузке. Затем библиотека
самостоятельно сформировала пакет из XML и создала версию 7 с изменениями пяти
свойств: `Synonym`, `NamePrefix`, `Vendor`, `Version`, `UpdateCatalogAddress`.
Версия 7 выгружена Конфигуратором в `.cf`, загружена в отдельную базу и выгружена
в XML. Полный `Configuration.xml` совпал с ожидаемым документом; UUID языка
сохранился, тестовый захват снят.

Проверки Python: `python -m unittest discover -s tests -p "test_*serializer.py"`.
Проверки разбора серверного контекста: `oscript tests/check-serializer-context.os`.
Интеграционная проверка `tests/integration-serialize-comment.os` принимает
JSON хранилища, JSON разработчика, пути к исходному и изменённому XML, Python,
каталог результата и режим `prepare` или `commit`. Последний необязательный
аргумент `properties` выбирает `ПодготовитьСвойстваИзXML`, без него проверяется
прежний метод изменения комментария. Режим `commit` создаёт одну
версию в тестовом ProtocolLab и снимает собственный захват после подтверждения.

### Создание строковой константы из XML

`ПодготовитьСозданиеКонстантыИзXML(Корень, XMLКонстанты, ПутьPython)` возвращает
`ПакетСозданияКонстанты`. `XMLКонстанты` — содержимое отдельного файла
`Constants/Имя.xml`, UUID должен быть новым. Корень получают через
`ПолучитьОписаниеОбъекта(UUIDКорня)`. Загрузка XML в подключённый Конфигуратор
не требуется: пакет строится Python 3.9+ из XML, свежих снимков и серверного контекста.

Поддерживаются платформы **8.5.1.1529 и 8.5.4.1878**, плоская конфигурация с языками и константами.
У новой константы можно задать `Name`, `Synonym`, `Comment` и тип `xs:string`
с переменной длиной **1..1024**. Остальные свойства должны иметь проверенные
значения по умолчанию; неподдерживаемые изменения отклоняются до отправки.
Минимальный XML и подробный порядок работы приведены в
[описании сериализатора констант](docs/constant-serializer.md).

```bsl
Корень = КлиентХранилища.ПолучитьОписаниеОбъекта(UUIDКорня);
Пакет = КлиентХранилища.ПодготовитьСозданиеКонстантыИзXML(Корень,
    XMLКонстанты, "C:\Program Files\Python39\python.exe");

// В пакет входят корень и все его непосредственные дочерние объекты.
// Их версии обновляются одним помещением; требуются собственные захваты.
Для Каждого Объект Из Пакет.СуществующиеОбъекты Цикл
    КлиентХранилища.ЗахватитьОбъект(Объект);
КонецЦикла;
Константа = КлиентХранилища.ПоместитьСозданиеКонстанты(Пакет, "Константа из XML");
// После успеха освобождаем захваты по актуальным описаниям.
Для Каждого Объект Из Пакет.СуществующиеОбъекты Цикл
    КлиентХранилища.ОтменитьЗахватОбъекта(
        КлиентХранилища.ПолучитьОписаниеОбъекта(Объект.Идентификатор));
КонецЦикла;
КлиентХранилища.ОтменитьЗахватОбъекта(Константа);
```

Подготовка не выполняет захват или помещение. Перед отправкой проверяются
версии, собственные захваты всех исходных объектов и отсутствие нового UUID.
После отправки сверяются версии, UUID содержимого и описания объектов на сервере.
Захваты сохраняются. После ошибки отправки сначала проверьте историю: автоматического
повторения помещения нет. Пример с обработкой ошибок есть в интеграционном тесте.

Без `InternalInfo` сериализатор генерирует шесть UUID типов; если раздел присутствует,
использует проверенные UUID из XML. Создание произвольных объектов и сериализация
всей конфигурации пока не поддерживаются. Требуется существующий корень хранилища;
значение константы в информационной базе этот метод не устанавливает.

Проверено на ProtocolLab: Python создал строковую константу длиной 128 в версии 9,
OneScript — длиной 64 в версии 10. Результаты получены через API, штатно выгружены
в CF и XML; UUID, типы, `InternalInfo` и сохранность прежних свойств подтверждены.
Проверки OneScript: `oscript tests/check-create-constant.os`.
`tests/integration-create-constant.os` принимает JSON хранилища, JSON разработчика
и путь Python. По умолчанию только готовит пакет. Явный четвёртый аргумент
`--commit` создаёт `CRSAPI_OneScriptConstant` в ProtocolLab и освобождает тестовые
захваты; если имя уже существует, подготовка отклоняется.

### Отмена захвата объекта хранилища

```bsl
КлиентХранилища.ОтменитьЗахватОбъекта(Объект);
```

Метод отменяет захват одного объекта текущим пользователем, без дочерних объектов.
Принимает актуальное описание `ОбъектХранилища` и необязательный
`ИдентификаторПодключения`, как `ЗахватитьОбъект`.
Возвращает `Истина` после подтверждения свободного состояния сервером.
Для уже свободного объекта также возвращает `Истина`.
Чужой захват, устаревшее описание, отсутствующий или удалённый объект и ошибки
сервера приводят к исключению. Принудительное снятие чужого захвата не выполняется,
в том числе при подключении администратором.

Отмена не помещает изменения в хранилище и не меняет локальные файлы конфигурации.
Проверено на **8.5.4.1878**; сценарии отмены включены в
`tests/check-capture-object.os` и `tests/integration-capture-object.os`.

### Создание пользователя хранилища

Пример создания нового пользователя хранилища:

```bsl
// ...
ИмяПользователя = "Иванов Иван";
Пароль = "12345";
Роль = РолиХранилища.Разработчик;
КлиентХранилища.СоздатьПользователя(ИмяПользователя, Пароль, Роль);
```

В случае неудачи будет вызвано исключение с текстом ошибки.

У `РолиХранилища` доступны значения:
* `ТолькоПросмотр` - дополнительных прав в хранилище не выдано
* `Разработчик` - возможность захвата объектов в хранилище
* `РазработчикРасширенный` - возможность захвата объектов и изменения состава версий в хранилище
* `Администратор` - полные права без ограничений

### Поиск пользователя хранилища

Существующего пользователя хранилища можно найти по его имени.

```bsl

ИмяПользователя = "Иванов Иван";
ПользовательХранилища = КлиентХранилища.НайтиПользователя(ИмяПользователя);
```

Если пользователь найден, то `ПользовательХранилища` будет содержать объект со свойствами:
* `Идентификатор` - идентификатор пользователя в хранилище, принимает значение формата GUID
* `Имя` - имя пользователя
* `ХешПароля` - хеш пароля пользователя
* `Роль` - роль в хранилище
* `Активен` - признак авторизации пользователя
* `Удален` - признак деактивации пользователя

Если пользователь не найден, то `ПользовательХранилища` будет равен `Неопределено`.

### Удаление пользователя хранилища

Для удаления пользователя в хранилище, нужно знать его идентификатор.
```bsl
// ...
ИмяПользователя = "Иванов Иван";
ПользовательХранилища = КлиентХранилища.НайтиПользователя(ИмяПользователя);
КлиентХранилища.УдалитьПользователя(ПользовательХранилища.Идентификатор);
```

При неуспешном удалении (деактивации) будет вызвано исключение с текстом ошибки.

### Восстановление пользователя хранилища

Для восстановления существующего пользователя в хранилище, нужно знать его идентификатор.
```bsl
// ...
ИмяПользователя = "Иванов Иван";
ПользовательХранилища = КлиентХранилища.НайтиПользователя(ИмяПользователя);
КлиентХранилища.ВосстановитьПользователя(ПользовательХранилища.Идентификатор);
```

При неуспешном удалении (деактивации) будет вызвано исключение с текстом ошибки.

### Изменение пользователя хранилища

Изменение пользователя может понадобиться для следующего:
* Изменение имени пользователя
* Смена пароля
* Изменение роли

В случае неудачи изменения данных пользователя будет вызвано исключение с текстом ошибки.

#### Изменение имени пользователя хранилища

```bsl
// ...
ИмяПользователя = "Иванов Иван";
ПользовательХранилища = КлиентХранилища.НайтиПользователя(ИмяПользователя);
// ...
ПользовательХранилища.Имя = "Иванов И.И.";
КлиентХранилища.ОбновитьПользователяХранилища(ПользовательХранилища);
```

#### Изменение пароля пользователя хранилища

```bsl
// ...
ИмяПользователя = "Иванов Иван";
ПользовательХранилища = КлиентХранилища.НайтиПользователя(ИмяПользователя);
// ...
ПользовательХранилища.Пароль = "qwerty51";
КлиентХранилища.ОбновитьПользователяХранилища(ПользовательХранилища);
```

#### Изменение роли пользователя хранилища

```bsl
// ...
ИмяПользователя = "Иванов Иван";
ПользовательХранилища = КлиентХранилища.НайтиПользователя(ИмяПользователя);
// ...
ПользовательХранилища.Роль = РолиХранилища.Администратор;
КлиентХранилища.ОбновитьПользователяХранилища(ПользовательХранилища);
```

### Получение списка пользователей хранилища

Для получения списка пользователей хранилища (включая "удаленных"):
```bsl
// ...
СписокПользователей = КлиентХранилища.СписокПользователей();
```

`СписокПользователей` будет содержать массив объектов `ПользовательХранилища`.

### Получение список версий в хранилище

Для получения списка версий в хранилище:
```bsl
// ...
СписокВерсийВХранилище = КлиентХранилища.СписокВерсий();
```

`СписокВерсийВХранилище` будет содержать массив объектов `ВерсияХранилища`. Из объекта `ВерсияХранилища` доступны следующие свойства:
* `Идентификатор` - внутренний идентификатор версии (GUID)
* `Номер` - порядковый номер версии
* `Дата` - дата создания версии
* `ВнутренняяВерсия` - внутренняя версия конфигурации
* `Версия` - версия конфигурации
* `Пользователь` - автор версии
* `Версия1С` - номер версии платформы 1С, под которой была создана версия
* `Комментарий` - комментарий к версии хранилища
* `Данные` - данные конфигурации, пока закрытый пакет

Экспериментальный метод `ПолучитьКлассыМетаданных(Корень, ПутьPython)` читает
UUID классов верхнего уровня из снимка корня, включая пустые коллекции.
[Описание метода и границ каталога](docs/metadata-classes.md),
[51 класс, полученный из тестового хранилища](docs/metadata-classes-observed.md).

На данный момент библиотека имеет следующие ограничения:
* Новое хранилище 1С создается из встроенного шаблона конфигурации 1С (пустая конфигурация)
